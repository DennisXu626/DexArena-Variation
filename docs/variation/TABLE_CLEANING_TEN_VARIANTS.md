## 验证计划

覆盖 `TableCleaningPickDebris-Sharpa-v1`、`TableCleaningDumpDustpan-Sharpa-v1`、`TableCleaningLong-Sharpa-v1`。拟用 Sharpa、2env、PhysX CUDA＋GPU 渲染、seed7、robot noise0；服务器实际软件、资产和源码版本写入 manifest。

1. **接入与静态审核**：默认关闭委托原任务；未知 ID 在写入前拒绝；catalog 与独立审核契约分别核对，加入 ID 对调反例。核对实际绑定槽、糖块纹理像素、原版恢复、逐环境材质独立性，以及碰撞/质量/惯量/物理材质等签名。保留 PR12 单环境、reset 返回计数和 state restore 缓存回归。
2. **外观预览**：真实任务中的簸箕、桶、糖块近景，以及三入口 original＋十套同机位图。检查握套与桶纹理保留、三粒碎屑均绑定正确；遮挡目标不得仅凭场景差分判为通过。受控摆放图与正式初态图分别标注。
3. **A4 全量检查**：三入口各十一种，共33行。对照实际 ID、外观绑定、物理与控制初态、初始 evaluate/obs/reward/info。Dump 默认预装载与 Pick/Long 桌面散落分别核对，保留静态桶原建场位置语义。
4. **A5 双向局部 reset**：十套各 reset env0/env1，三入口共60例，覆盖切入方案与恢复 original。原生与候选同步执行相同 full/partial reset、render/readback 历史；保存当前原生前后签名与图像。核对未选环境的位姿/速度、活动控制目标、任务计数/锁存/缓存、材质、记录、任务 RNG 和全部相机 RGB。恢复 original 对照匹配历史原生，不能对照一张固定旧图。
5. **复现与短步**：若保持现有显式接口，不新增随机选皮肤 API；以固定 seed 重放原任务随机布局序列，并复现受控方案切换序列。三入口各十一对，共33对同动作四步；原生与候选采用独立 Python worker 串行运行，各自仍为2env。先比对机器人/物体、控制器及 drive targets/velocities，再比较四步状态、奖励、terminated/truncated 与 info。
6. **任务临界隔离**：受控构造拾取 HOLD_STEPS 前一计数、倒入 DUMP_HOLD_STEPS 前一计数与阶段锁存状态，双向局部 reset 检查邻居；验证同帧重复 evaluate/obs 不虚增计数、运动缓存不串行、reset 返回结果对应新初态。覆盖 set_state_dict/reset_to_env_states 在同一步号恢复碎屑移动后的缓存失效，包含 task_state 有/无两种情况。Dump 补测 start_loaded=False。用例数待脚本设计时按真实字段冻结，不冒称完整机器人轨迹。

浮点状态起始标准为 atol=1e-6、rtol=0；恢复目标与未选行 RGB 起始标准为最大差1、最多8通道，不继承 Meal 专用例外。出现超限先进行原生重复与匹配历史诊断，保留失败证据，不自动放宽门槛。
