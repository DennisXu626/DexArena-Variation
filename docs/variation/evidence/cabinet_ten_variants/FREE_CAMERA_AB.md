# 正式任务相机的自由盖 A/B 对照准备

唯一问题是原生外观关闭与家族 `variant_9` 在生产切盖后，正式任务相机中是否都出现目标消失或大块前景替换。[129056 的补充机位异常及已通过分项](runtime_006/README.md)继续保留。原标签区域 1,487 像素的历史分解只用于补充机位对照，正式相机使用各自附着帧的固定瓶分割区域。

| 项目 | 固定条件 |
| --- | --- |
| A 原生关闭 | 独立任务实例，构建和 reset 均省略 `family_appearance` 与旧外观配置。核对家族和旧适配器均未启用。 |
| B `variant_9` | 独立同任务实例，只增加显式家族外观配置，核对两环境实际方案。 |
| 两组 | 同一冻结生产源码及资产、`physx_cuda`、seed 7、每组双环境。核对 reset 物理状态指纹和实际相机配置／参数。仅在环境 0 设定 129056 的工程触发输入，生产 `evaluate()` 执行切盖，环境 1 保持附着。 |
| 相机 | 省略 `sensor_configs`，正式 `base_camera` 与 `task_wrist_camera` 使用任务默认 256×256、视场、位姿与挂载。`render_camera` 用 129056 的补充机位。 |
| 顺序 | 先存附着末帧。切换后先用生产 `get_obs(info=existing_info, unflattened=True)` 取得正式两路 RGB 与实体分割，再采补充机位。传入已有 `info` 避免重复 evaluate。记录实际调用，切换后无物理推进、相机位姿写入或预热帧。 |

双环境的每台相机保存 RGB、完整实体分割（RGBA 打包小端 `uint32`）及内外参。记录固定瓶、附着盖、自由盖、`mobile_base_link_6` 和瓶／盖放置区的实体 ID、物理位姿与渲染可见性。若引擎可读，双相机采集步骤完成后另存每环境原始渲染变换数组；SAPIEN 3.0.3 的 Python 接口未公开图元对应的数组行，原始矩阵不冒充逐实体渲染位姿。此 getter 会准备渲染器变换缓冲，因此只在正式和补充相机都采完后回读。 [SAPIEN 3.0.3 回读实现](https://github.com/haosulab/SAPIEN/blob/731622eac5b140b320076c8a1b6eb4b553c3ccd4/src/sapien_renderer/sapien_renderer_system.cpp#L183-L199)

每格先核对该机位附着帧看得到固定瓶和附着盖。若缺目标、相机参数或固定瓶物理位姿改变，标不可判定并留原图。其余情况下，固定瓶或自由盖为零像素，或原瓶区被非盖体的其他前景占据过半，标复现。其余标未复现。并列记录环境 1 的 RGB、完整分割和相机一致性。复现是有效比较结果，A 组复现后继续 B 组。资源保护触发、采集失败、切换失败或两组初态／相机不一致时停收后续证据。

本轮 CPU 检查覆盖默认相机无覆盖、正式先采集、RGB/分割无损落盘、判定分支及未批准拒绝。未运行任何 GPU 作业。申请一次单卡 180 GPU 分配秒，应用 150 秒，45 分钟总窗口含至少 15 分钟收尾。只读复用 `runtime_006` 冻结生产源码，新增 `runtime_007`，整根预提交仍为 680 MiB、运行每秒采样停止仍为 768 MiB。待 Dennis 确认，草稿不合并。
