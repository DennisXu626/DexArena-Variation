## 首个失败点

部署时复用了 `runtime_006/source`，校验了冻结文件，并用 bwrap 的 `--chdir` 和只读绑定通过 CPU 预检。实际作业另经已有 `guard_core.run_owned()` 启动应用，其第 74 行先向 `Popen` 传入 `cwd=root/'source'`。运行目录是 `runtime_007`，该目录下没有 `source`。应用子进程创建前即报 `FileNotFoundError`，因此 bwrap 的工作目录选项尚未执行。我在预检中漏查了外层进程创建使用的工作目录。

若另行批准复测，最小修复是在新运行目录准备并验证外层要求的空 `source/` 工作目录，同时保持 `--chdir` 指向同一只读生产树。在提交前用无仿真 CPU 替身经过与正式作业相同的 `run_owned()` 启动路径，验证工作目录和退出收据。本轮保留原启动现场。
