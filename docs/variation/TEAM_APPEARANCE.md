保持几何、碰撞、质量、关节和任务判定不变；优先利用原材质与UV，不为换外观重建模型。保留按钮分界、开口、插孔和非对称转动标记等任务细节。遇透明材质、共享贴图、多阶段表示或新加载路径，先记录具体适配问题并协调。

## 职责和交付包

实习同学负责可供接入的外观包：部件分析、方案／素材制作、预览应用及资料整理。Dennis统一组织正式任务接入、固定／随机选择与回合记录、阶段一致性、物理不变及并行局部reset隔离（A4／A5），并审阅结果。同学不必独立完成A4／A5才能提交素材，也不各建一套验证框架；预览若需修改共享加载器或处理环境问题，先交接给统一执行层。

| 每对象交付项 | 内容 |
|---|---|
| 部件对应表 | 模型／link／材质槽到外壳、按钮等角色的映射；一起变化与保留的部件；不同任务／阶段的表示 |
| 外观方案与素材 | 方案ID、材质参数、实际使用的贴图和必要制作脚本；没有新增UV／贴图则明确写无，不制造占位文件 |
| 原版／候选对照 | 同初态、同相机、同光照的整体与必要局部图；标清模型查看器预览或真实任务渲染 |
| 复现与来源 | 制作方法、应用／预览命令、原资源入口与身份、第三方素材来源及许可 |
| 交接状态 | 素材完成、接入完成、运行验证完成分别标明；列出未测项、待接入任务和已知问题 |

没有可用运行环境时，先交素材与草稿PR，将任务实景列为待补，由统一执行层安排；模型预览不能写成任务运行通过。GPU及其它资源仍按现有规则单独授权，任务分工不构成运行预算。

## 存哪里、怎么交

1. 先读[仓库README](../../README.md)、[贡献规范](../../CONTRIBUTING.md)、[外观档案入口](../../assets/appearance/README.md)及自己的[对象清单](../../assets/appearance/objects.csv)。[瓶身档案](../../assets/appearance/objects/cabinet_pouring/bottle/README.md)可参考资料组织；[Charger说明](CHARGER_APPEARANCE.md)可参考纯材质方案交付。
2. 使用现有 `assets/appearance/objects/<family>/<object>/` 档案位置，按需存放参数、小素材、制作方法、绑定说明和证据入口。运行catalog已存在时引用唯一来源，不维护第二份独立参数源；未接入的方案明确标注待接入。
3. 从最新main开任务分支。首个样例一个PR；之后按家族拆成可审阅的小批次，不等四个家族全做完才交，不多人共用开发分支。
4. PR附对象／方案清单、对照图、复现命令、已做检查及待接入项，将PR链接发给Dennis。不要只交个人本地路径或聊天截图；外部证据使用团队可访问入口。
5. 按贡献规范完成适用的静态检查与审阅。只提交代码、配置、小型自制素材及精简文档，原模型、缓存、大型输出和环境不整包上传。素材完成不自动将对象标为运行已验收；总索引／能力状态由集成验收后同步更新。

本安排不改写历史验收结论；正式接入的验证要求保留，由Dennis统一组织完成。
