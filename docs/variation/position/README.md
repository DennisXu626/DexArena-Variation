# 场景位置 variation 工作指南

接手一个家族时，先选一个短任务，写清楚「物体从哪里开始、手要怎么接近、任务在什么条件下结束」。据此提出能产生不同操作体验的位置和朝向，画出边界，再用真实环境做初始化和粗略可达性检查。交付目标是让遥操作同学能复现一个具体初态、实际操作，并指出哪一侧需要调整。每个场景单独定范围。

## 1. 先选值得变化的物体

按短任务查看原生 `make/reset`、实际加载的物体、关节开度和成功判据。分别记录**起点、目标、下一阶段起点**。例如，`PickBottle` 的起点在已开门的柜内，桌面盘是它的放置目标，也是 `UnscrewCap` 的起始区域。共用交接区时，两边都要查。某个阶段会换成固定瓶、自由盖等另一实体时，核对该阶段实际使用的实体。

先给负责人看一张范围表，每项变化占一行。下面三行取自已交付的场景。

| 短任务及变化 | 相对谁、怎样变 | 为什么变，边界由什么决定 |
|---|---|---|
| OpenDrawer · 整柜平移 | 世界桌面 XY，柜根相对标称值两轴各 ±5 cm | 改变伸手距离。把手、滑轨和中屉随柜体走，检查开屉时的空间 |
| PickBottle · 层板瓶位 | 柜体局部 XY，随柜一起平移和转动 | 改变伸入和退出路径。瓶底要完整落在层板上，手指能靠近，瓶能退出柜口 |
| InsertPlug · 插座朝向 | 桌面法向转动，已实现 85°、90°、95° 三档 | 改变预对准方向。壳体和两孔一起转，核对双插脚与实时孔位的关系 |

为自己的每一行补上标称值、旧域、候选新域、单位、连续或离散、适用阶段，以及同场必须跟随或避开的物体。特别写清**物体相对容器的运动**和**容器带着物体的运动**。例如柜体转 5°，里面的充电器世界朝向也会变，但它相对抽屉的朝向仍相同。扩大区域或增加自由度时，先与负责人确认候选。

## 2. 每项变化单独出一张边界图

- **一图回答一个问题。** 同一个柜子的 XY 和朝向分两张。桌面任务保留完整桌面俯视图，并给一幅等比例局部放大。固定其余变量，标明固定值。相关障碍物保留在图里作参照。
- **统一图例。** 浅米色只填真实桌面，深线描真实桌边，灰色为旧域，蓝色为新域，红点为标称中心，白点为有编号的样点。标称点与新域中心不同就都标出。轴上标坐标系和单位，直接在图形上标物体名。
- **把会碰到的东西画出来。** 用实际支撑面和碰撞轮廓画瓶底、把手、插脚、门和抽屉前沿。区分物体中心采样域、完整占地和放置成功区。转角图固定旋转中心，跟踪同一个把手、壳角或插脚。开门和拉屉还要看中途扫过的位置。俯视重叠时标明高度和所处阶段。
- **把最紧的位置写在图上。** 标出对应样点、最近桌边或障碍物的余量，并注明来自静态几何还是 reset 后实测。使用现成画法可对照 [Cabinet 柜门与瓶区](../evidence/cabinet_position_boundaries/04_table_handoff.png) 和 [Drawer 充电器与桌边](../evidence/drawer_position_boundaries/04_charger_table_handoff.png)。

## 3. 接入初始化，并在真实后端测边界

沿用该任务已有入口，省略配置时保留原生初始化。显式请求要能复现到指定环境，越界请求要明确拒绝。记录局部坐标的原点和正方向，区分绝对坐标与相对偏移。容器有活动关节时，按实际父子关系变换到世界坐标。例如屉内物体按零开度坐标给定时，转换中要计入本次抽屉行程。直接从 reset 后的有效物体读取位置、朝向和阶段，与请求对照。机器人初态、物理和成功判据沿用原任务。两个家族的入口可查 [Cabinet 位置解析](../../../tasks/cabinet_pouring/position_layout.py)、[Cabinet 桌面交接区](../TABLE_XY_VALIDATION.md) 和 [Drawer 位置解析](../../../tasks/drawer_plug/position_layout.py)。

| 要回答的问题 | 怎么测，怎样记结果 |
|---|---|
| 边界真的能生成吗？ | 先测标称点。圆域可取中心加八个方向。矩形取角点和边中点。转角取两端和标称角。再加少数最不利组合，例如最远柜根＋最大转角＋最深物体，以及刚好越界的请求。逐点记请求值、实测值、拒绝原因。 |
| 初态能站住、放得下吗？ | 查完整底面、侧壁、上缘、运动路径及相邻物体。对靠桌边或容易倾倒的物体，做短时释放，记录位移、倾斜和支撑。浮点边界保留原点和原判据，可另做向内少量偏移的对照。 |
| 手大致能到吗？ | 在同一初态先测标称，再沿边界测任务相关的接近姿态，例如把手外侧、壳体抓取面、双孔上方。记指尖或末端 IK 误差与门槛。疑难点可做一次短拉、提起或预对准。最终是否好操作交遥操作判断。 |
| 只重置一个环境会怎样？ | 对支持并行的入口，用两个环境分别只 reset env0、只 reset env1。选中环境核对实测位姿，另一个环境比较物理和任务阶段状态。两次快照间不推进物理。若检查器人工挪动物体来测判据，读数后立即恢复物体与相关缓存，再测下一点。[充电器九点回滚实例](../evidence/drawer_position_boundaries/f4_followup_002/RESULTS.md) |

**怎么决定收不收范围？** 实测悬空、穿透、违反约定的支撑条件或任务阶段改变，就定位到对应一侧或组合，修正后补测。初态合法而某个 IK 点没过，先对照标称点，保留失败行和原因，交遥操作复试。报告分别写初态、IK、实际短动作和人工试用结果。先完成静态核对，再向负责人报本轮作业次数、GPU 与墙钟预算、落盘路径、容量和停止条件，获批后运行。

## 4. 交给遥操作同学什么

每个家族用一个 PR 交付范围表、各项独立 PNG、逐点 CSV、可复制的 `make/reset` 调用和运行报告。逐点表至少能找回 **任务 ID、样点 ID、seed、env_idx、构建参数、reset 请求、实测位姿和各项结果**。复现时用同一后端与版本，按记录的构建及 reset 顺序操作。将「可初始化样点」和「为检验成功判据而人工摆出的点」标成不同类别。

在 PR 里给操作者点名一个标称点和少数最值得试的边界点，说明要做哪个动作。请操作者回传样点 ID、在哪一步受阻、从哪侧接近更顺手，由场景负责人决定保留哪一段范围。下面两条记录可直接复现。

| 家族 | 从哪里复现 | 已知边界 |
|---|---|---|
| Cabinet & Pouring | [四任务报告与调用](../evidence/cabinet_position_boundaries/runtime_002/RESULTS.md) · [逐点表](../evidence/cabinet_position_boundaries/runtime_002/POINTS.csv)。`PickBottle / C0`，seed 767、env1，试远柜根和深角组合下抓瓶并退出。 | 76/76 合法初态通过，71/76 指尖 IK 通过，20 次短动作均未达各自门槛。 |
| Drawer & Plug | [三任务调用](../evidence/drawer_position_boundaries/runtime_001/RUN_AND_REPLAY.md) · [逐点表](../evidence/drawer_position_boundaries/runtime_001/POINTS.csv)。`PickCharger / C-deep-minus`，seed 876、env0，试从深侧抓壳体并越过抽屉前沿。 | 62/62 合法初态通过，39/62 指尖 IK 通过，2 次短动作均未达标。充电器放置沿用严格小于 14 cm 的距离条件。[九点补验](../evidence/drawer_position_boundaries/f4_followup_002/RESULTS.md)保留了精确边界读数。 |

**屉内充电器还有一项候选扩展。** 已发布版本支持相对标称点左右 ±2 cm、进深 ±1 cm，充电器侧躺并随柜体转动。下一版候选为左右 ±4 cm、向屉口最多 3 cm、向深处最多 1 cm，再加相对抽屉连续转 −45°～+45°。这些新数值尚未实现或验收。若接手该项，将平移和自身转角各画一张图，重点检查角落叠加转角时双插脚、侧壁和手指的空间。
